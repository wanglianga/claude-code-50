# 城市夜间药房急症配药与处方核验平台

Vue 3 + Spring Boot 3 + PostgreSQL，Docker 一键部署。患者/家属深夜下单后，患者、药师、收银、仓管、配送员、客服在**同一张配药单**上协同，每一次“继续配药 / 暂停配药 / 改为线下复诊”都记录原因，次日可从同一档案回溯审方→出库→支付→签收到投诉处理的全过程。

## 原始需求

> 建设城市夜间药房急症配药与处方核验平台，可采用 Vue 3、Spring Boot 和 PostgreSQL。患者或家属在深夜提交病症、电子处方、医保凭证、过敏史、既往用药和是否需要配送后，平台先判断处方有效期、药品管制类别、库存批号、冷藏要求和药师值班状态。药师审方时要看到医生签名、剂量、禁忌、重复用药和替代药建议；若处方字迹或图片不清，药师可退回补充，也可联系患者确认关键药品。医保核验通过后，平台计算自费、统筹、门诊慢病额度和夜间服务费。若药房缺药、药品临期、患者要求改配送地址、骑手无法保冷或医保接口返回异常，平台要把患者、药师、收银、仓管、配送员和客服放在同一张配药单上协同处理。药品出库后，批号、药师审方意见、付款明细、配送温控照片、签收人和用药提醒进入档案；若次日患者反馈不良反应、漏发药品或医保扣费争议，客服能从同一配药记录追到审方、出库、支付和签收过程。平台还要处理夜间值班药师交接、急诊医生电话核实、管制药品限购、发票抬头和医保回退，确保每一次修改都能解释为什么继续配药、暂停配药或改为线下复诊。

## 能力与需求对照

| 需求 | 实现 |
| --- | --- |
| 深夜提交病症/电子处方/医保凭证/过敏史/既往用药/是否配送 | 患者端“深夜配药申请”，处方图片上传归档 |
| 自动判断处方有效期、管制类别、库存批号、冷藏、药师值班 | 提交即跑 5 项自动核验，结论写入事件流；**过期处方提交即暂停（EXPIRED 事件），审方/医保/支付/恢复全链路硬阻断，只能重开处方或转线下**；管制超量自动暂停、无值班药师自动转线下 |
| 审方：医生签名、剂量、禁忌、重复用药、替代药 | 审方意见自动汇总四要素 + 医生签名；管制药强制先走急诊医生电话核实 |
| 处方不清退回补充 / 联系患者确认关键药品 | “退回补充”（单据暂停，患者可重传清晰处方）、“联系患者”沟通留痕 |
| 医保核验与费用拆分 | 医保 mock（尾号 `ERR`=接口异常、`000`=拒付、其余通过）；自动拆分自费/统筹/门诊慢病额度/夜间服务费（药费 15%，最低 6 元） |
| 缺药、临期、改地址、骑手无法保冷、医保异常协同 | 同一单据上：替代配发/移除并重算费用、地址变更留痕、骑手保冷确认（不能保冷自动暂停）、医保重试/回退 |
| 出库批号/审方意见/付款明细/温控照片/签收人/用药提醒入档案 | 出库冻结批号效期并扣库存；冷链签收强制温度(2-8℃)+照片；签收页记录用药提醒 |
| 次日不良反应/漏发/医保争议可追溯 | 投诉台按环节定位（审方/出库/支付/配送），从同一配药单时间线回看全程 |
| 药师交接、急诊医生电话核实、管制限购、发票抬头、医保回退 | 班次交接（在途单据随单改挂接班人）、管制药夜间限购 2 份+医生电话核实、支付时录发票抬头、医保异常可回退全自费 |
| 每次修改都能解释为什么继续/暂停/转线下 | 所有操作写 `order_events`：操作人、角色、状态前后、决策类型、文字原因 |
| 患者数据隔离与员工协同 | 患者只能查看/操作**本人**配药单（跨患者访问详情、暂停、恢复、转线下、改地址、投诉、补充处方一律 403）；药师/收银/仓管/骑手/客服按职责在同一单据上协作 |

## 一键启动（宿主 Docker）

```bash
cp .env.example .env        # 端口/账号可按需修改
docker compose up -d --build
# 查看健康状态
docker compose ps
# 应用端口以实际映射为准：
docker compose port app 8080
```

浏览器访问 `http://<宿主IP>:${CC_PUBLISH_PORT}/`（本评估环境为 `http://host.docker.internal:3050/`）。
数据库**不发布**宿主端口，只在 compose 内网通过服务名 `postgres` 访问。

停止并清理：

```bash
docker compose down          # 保留数据卷
docker compose down -v       # 同时删除数据库与上传文件卷
```

## 验证方式（= 宿主 docker compose up）

本工程在隔离容器内构建：多阶段 `Dockerfile`（node:20 构建前端 → maven:3.9-temurin-17 构建后端 → temurin-17-jre 以非 root 用户运行，含 `HEALTHCHECK`）；`docker-compose.yml` 仅发布 app 端口（`${CC_PUBLISH_PORT}:8080`），postgres 不发布。以 `GET /api/health` 返回 `{"success":true}` 与端到端业务流（登录→提交→审方→医保→支付→出库→冷链签收→投诉追溯）走通为验收标准。

## 技术结构

```
backend/   Spring Boot 3.3 + Spring Data JPA + PostgreSQL
  domain/      User Drug DispenseOrder OrderItem OrderEvent Complaint PharmacistShift
  service/     OrderService（协同状态机+决策事件流）、InsuranceService（医保mock）、Requests(DTO)
  web/         认证/单据/药品/班次/投诉/上传/健康 控制器 + Token 会话拦截器
  config/      DataInitializer 演示数据、SPA 回退、全局异常
frontend/  Vue 3 + Vite + Element Plus + vue-router
  views/       Login NewOrder Orders OrderDetail Drugs Shifts Complaints
```

说明：医保为内置模拟接口（凭证号规则见上），非真实医保局对接；会话为轻量 Token 实现，便于评审环境零外部依赖一键运行。
